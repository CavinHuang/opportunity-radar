# 来源级误报与漏报复核（只读）

这一轮复用 **真实问题发现质量** 的 `discovery_quality_labels`、当前生产候选 `opportunityScanCandidates`、首页候选反馈 `home_opportunity_feedback` 和研究建议反馈 `opportunity_research_guidance_feedback`，没有新建或改变评分规则。

## 为什么新增这个诊断

已有全局误报、漏报和人工标注率，但看不出是单个信息源持续引入营销内容，还是单个社区的真实操作问题被过滤或者在前 50 名榜单中丢失。这一报告按**原帖域名**组织来源级错误和人工复核队列，帮助 Owner 找到下一条应读的原始帖子。

- 范围与主扫描一致：最近读取的最多 400 条 `new/saved`、HTTPS 且具有标题的来源记录；候选榜单为前 50 名。
- 只把来源 `revision` 与标注 `sourceRevision` 一致且 `real_problem` / `not_problem` 的记录计入 TP/FP/FN/TN。标注过期、不确定、窗口外分别计数，永不补成“已验证需求”。
- 漏报含规则过滤、聚合未展示和前 50 名截断，必须人工复核原因。
- 默认复核顺序：已标记的漏报 → 已标记的误报 → 过期标注 → 不确定 → 未标注负例 → 未标注正例；同优先级跨域名轮转，避免同一来源占满队列。
- 仅有效标注数至少 10，且对应精确率/召回率分母至少 5 时才展示该来源**人工标注样本内**的比率。没有足够数据时不展示百分比。
- 关联首页“有用 / 误报”与研究建议“采纳 / 调整 / 拒绝 / 结果回填”作为**上下文备注计数**，不折算为准确率、不归因为转化、也不计作独立使用者。
- 仪表盘按域名显示，不会因误报率、采纳数或反馈自动禁用来源、修改扫描策略、提高机会排名。

## 使用

在 **机会简报 → 信息源与信号 → 真实问题发现质量** 展开区域点击 **来源错误归因**。阅读来源级差异，点原帖检查，再使用 **人工核查** 回到已有的标注流程。已修订的记录自动按版本刷新统计。

`GET /api/discovery/source-cohort-quality?limit=18` 使用现有 Owner 认证，limit 为 1–50。只读，响应含 `totals`、`cohorts`、`queue`、`evaluatedRates`、`notice`；最多展示 40 个域名和 50 条复核项，所有信息基于本地 SQLite。

## 验证与边界

测试分别验证 TP/FP/FN/TN、过期/不确定/窗口外标注隔离、跨来源负例轮转、主观反馈与分类标签分离、HTTP Owner 鉴权与 SQLite 零写入；Chrome E2E 打开并关闭新增诊断窗口。

原帖和作者真实性仍然需要人工核查。人工标注本身有选择偏差；尤其不能用“这个来源的样本精确率”直接给来源排名，或以某次建议被采纳推导需求真实存在。真实生产数据不可用于合成测试，本轮 CI 均使用独立的测试数据库。
