# 研究结论 → 产品开发 → 真实使用反馈（v1.1）

## 已落地的端到端路径

1. 信息源工作台获取真实公开信号，研究证据中明确保留来源、反证和未经验证事项。
2. 在机会的「用户验证」中进行已获同意的真实访谈/行为观察，人工标注支持、反对与未知，关闭验证计划并明确做出 `continue` 决策。
3. 单独点击「启动产品实验」；只有当前机会最新一轮已关闭且 Owner 决策为 `continue`，才会随实验附上 `validationPlanId`。研发目标、验收条件、投入预算和停止标准仍需单独批准。
4. 项目基线冻结研究依据（计划 ID、批准时间、决策理由、支持/反证数量、不确定性），Coding Agent 使用 `project.get_context` 读取概要，**不包含逐条观察原话或匿名参与者代号**。
5. 用户点击项目首页的「准备首个研发任务」，将该版本已批准目标转为一条开放任务；外部 Coding Agent 可用 `project.get_next_work` 和 `task.claim` 领取。Radar 本身不启动外部进程。
6. Agent 使用现有 MCP 工具和 GitHub 提交、PR、必需 CI 记录交付，用户仍在 G4 阶段批准或退回；不能用 Agent 汇报替代验收。
7. 只有产品交付里程碑正式验收后，才允许在「结果与复盘」记录实际使用反馈，附匿名参与者代号、发生事实、时间与可复查来源（可选），并确认取得记录同意。

## API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/experiments` | 可选 `validationPlanId`；关联时须为本机会、Owner 已关闭并决定继续的计划 |
| POST | `/api/projects/:id/kickoff` | Owner 单独点击后生成当前基线的一条可领取任务；相同基线重复调用不会再创建 |
| GET | `/api/agent/tools/project.get_context` | 现有 Agent 业务工具，返回 `researchBasis`，不包含匿名用户或逐字访谈 |
| GET | `/api/projects/:id/feedback` | Owner 访问项目交付后的手工使用观察 |
| POST | `/api/projects/:id/feedback` | 仅在产品 G4 验收后有效；必须提供匿名用户代号、类型、记录、同意标记 |

## 安全与真实性界限

- 原始访谈由 Owner 录入；计划中的 `continue` 是用户做出的研究决策，**并不表示市场需求或付费意愿被独立核实**。
- 即使没有研究计划，也可兼容过去的研发项目；平台标识为 `unlinked`，不能称作研究证明成立。
- 完整研发审批与研究审批彼此独立。
- 启动任务前由 Owner 单独点击，任务描述依照当时的产品基线生成。修订基线后，旧版本尚待领取的 kickoff 任务会作废，新版本由用户重新准备。
- 使用反馈也只是 Owner-reported，平台不核验用户身份或访谈真实性。请勿录入姓名、电话号码、邮箱、敏感记录。匿名代号重复不累计为新用户。
- 此版本未进行真实消费者 T4 招募；GitHub Actions 使用隔离数据库与标记为测试内容的样本，只验证代码路径与行为，不代表市场成功。

## 工程验证

`npm run check`：单元 / 服务 / HTTP 测试。GitHub Actions `Direct browser E2E`：Chromium 直连本地 Node 及隔离 SQLite，操作研究计划、反证、决策、实验审批、首个任务与反馈验收门槛；不用伪造 UI API 响应。
