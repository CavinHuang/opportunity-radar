## 1. 冻结原则与产品目标

**北极星体验：** 每周用不超过 10 小时基线主动投入，由雷达推荐值得取证的消费者机会，经用户批准后交给一个外部专业 Coding Agent 完成交付，雷达用可核验证据提供真实进度，由用户完成验收；随后支持一次真实宣发、记录用户反应与现金/时间投入，并明确继续或暂停。

**首版成功不等于赚钱：** 必须证明一条可信的机会到真实用户反馈的工作链，而不是制造用户/收益数据或模拟 GitHub 绿灯。需要真实消费者、真实原型与真实外部证据；未发生付费允许记为 0，不能虚构。

**项目管理边界：** 不编写代码、不成为 IDE、不调度 Agent 进程、不管理其模型内部会话/子 Agent trace；只管理项目交付、证据与关键决策。

### 2.1 必须显式解决的冲突

1. **D32 vs 已批准 D76**：D32 设“三个一级空间（含完整个人资产库）”，而 D76 将历史复盘降为轻量入口。推荐执行 D76；D32 的独立完整资产库形态不进入 P0。除非用户特别修改 D76，否则不同时采用两个相互冲突的导航定义。
2. **D12/D20 vs 已批准 D81/D82**：宣发是核心闭环，但完整多平台运营、自动发布和高级增长分析均不进入 P0。保留必要的真实内容包、审核与手动发布记录。
3. **D17 vs D15/D74**：候选市场可同时观察国内外，但唯一主实验选择一个主市场；“自动影子市场监测”进入 P1。
4. **D21/D42 vs D82**：自然周期留存是记录口径，不要求实现复杂 cohort 分析。能够记录真实再次使用机会及行为即可。
5. **D40 vs D69**：低打扰已确认，但固定“三次打断”的硬上限可能阻碍必要审批/安全提示。先作为体验测量指标，再决定量化目标。
6. **D56/D57/D65 vs D77**：13 项工具是稳定长期契约，P0 只实现并启用单 Agent 所需 12 项；多 Agent 双向确认与 `collaboration.handoff` 交接实现进入 P1。不可声称 P0 已验证多 Agent。
7. **D54 与需求变更**：已批准 Baseline 不允许原地修改；用户批准变更后创建 Baseline rN+1，旧版本只读可追溯，Agent 旧任务需重校验。
8. **D68 与 D48/D50**：自动 G0/G1 核验不是 G4 用户验收；高于证据的产品质量结论不能由 Agent 自报覆盖。
9. **D79 与 D47/D59**：雷达支持外部 Agent 主动查询和恢复，但不保证 Agent 离线时持续执行，且撤销平台权限不等于外部执行进程停止。

## 3. P0 必须闭环的六个能力包

| 能力包 | 必须做到 | 明确不做 |
|---|---|---|
| A. 机会发现 | 允许少量可信公开/授权源及用户手动输入；独立来源去重；0–3 个候选；场景与证据；标记推断/未知 | 全网爬取、实时资讯流、复杂趋势预测 |
| B. 机会决策 | 对个人优势、需求真实性、用户可触达性、市场/渠道、最大失败原因做判断；批准唯一主实验；实验契约 | 伪精确综合评分、多个同时主实验 |
| C. Agent 项目 | 版本化批准基线；一个外部 Coding Agent 在外部启动；12 项授权内业务工具、任务租约、进度汇报、离线恢复 | IDE、Agent 进程调度、实时 trace、多 Agent 交接执行 |
| D. 交付验收 | GitHub 关联 exact commit、PR 与 CI；G0/G1 真实核验；验收点证据列表；三维状态；用户 G4 正式验收 | 代码审查 UI、自动正式验收、独立 Reviewer 强制配置 |
| E. 宣发协作 | 一个主市场+主要渠道，真实功能版本和素材关联；生成可编辑内容包；事实/隐私检查；用户手动发布并记录 | 自动发帖、自动私信、广告投放、复杂视频平台 |

### 3.1 信息架构（以已确认 D76 为基线）

- **机会简报（主入口）**：0–3 个值得关注的机会；如有主实验则突出当前唯一建议行动；同时显示不推荐原因。
- **当前主实验（主入口）**：一屏展示下一步、里程碑、三维进度、风险、最后同步、证据入口；分组呈现需求/交付/宣发/结果。
- **历史与复盘（次级入口）**：可查看已停止项目、经验、真实数据、素材和唤醒条件，不建独立复杂资产平台。

### 3.2 内容表达边界

默认图文、截图及产品录屏素材，真人出镜非前提；所有体验与功能声明追溯到已确认事实，不能编造个人故事、收益或用户评价。可以在产品完成前发布诚实标明“原型/需求研究”的内容，但不可伪称功能已交付。

## 4. 单项目生命周期与所需决策

1. **发现**：系统候选 0–3 项，明示消费者场景与证据不足；无合格线索允许零推荐。
2. **批准实验**：用户选中一项；填写并批准假设、主市场、试验范围、验收条件、10h 基线/可批准弹性预算、现金上限和停止条件；生成不可原地修改 Baseline r1。若还在需求取证阶段，可暂不启动 Coding Agent。
3. **启动外部 Agent**：雷达提供项目交接摘要与连接方式；用户在外部手动启动；Agent `project.get_context` 核对基线后领取任务。
4. **自主开发与汇报**：Agent 在授权范围内维护任务；低风险修复无需用户介入；报告的“完成”不等于验证成功；普通进展合并展示。
5. **交付与验收**：Agent 交付 commit/PR/CI、原型入口、验收项映射。雷达核对版本及检查；若失败则自动提示修复；若满足核验要求，用户检查并明确通过或退回。
6. **宣发验证**：基于相符版本准备单渠道内容，用户审核并手动发布，记录真实渠道/素材版本/反馈；可以在需求研究期提前开展诚实的传播验证。
7. **复盘退出**：记录目标人群是否能触达、是否完成关键任务、是否在自然需求发生时复用、真实付费/退款/相关成本；给出继续/取证/暂停/放弃与唤醒条件，用户确认。

## 5. Agent 接口 P0 范围（业务协议，不指定传输实现）

完整合同保留 13 项；**首版启用且必须可用的 12 项**：

| 工具 | P0 最小语义 |
|---|---|
| `project.get_context` | 返回用户已批准的项目基线版本、验收条款、授权边界、最后变更标识 |
| `project.get_next_work` | 只返回在当前权限和依赖约束下可以领取的任务 |
| `project.watch_changes` | 支持持久游标增量读取；首版可轮询，不要求服务端常驻推送 |
| `task.claim` | 领取有期限的责任租约；需检测既有归属与基线 |
| `task.upsert` | 在授权范围内增改执行子任务；需版本检查与幂等标识 |
| `task.transition` | 修改执行状态，不得修改用户验收结果 |
| `task.release` | 释放责任并记录原因，不等于停止外部进程 |
| `progress.report` | 报告进度、下一步、风险；归类为 Agent 自报 |
| `evidence.attach` | 关联版本化外部证据（commit/PR/CI/预览），未经查询核验不得称已验证 |
| `issue.raise_blocker` | 报告阻塞、影响、候选解决方案及是否需要用户决定 |
| `decision.request` | 请求超范围变更/追加预算/授权；不因提交申请而自动生效 |
| `handoff.submit` | 提交里程碑交付包申请验收；自动核验后仍需用户 G4 批准 |

`collaboration.handoff` 是第 13 项，**协议保留但 P0 不启用**，P1 实现双向交接。客户端必须正确获知可用能力，不可静默将不可用接口表现为成功。

### 5.1 写操作可靠性红线

每个写请求在逻辑上应绑定 Agent 身份、作用项目/任务、当前批准基线、期望对象版本、幂等标识与权限；租约超时需先核对外部副作用，不能直接推断停止执行或允许重入部署。过期/重复/冲突消息不能覆盖较新事实。批准记录和已审核内容不可被 Agent 文本冒充。

## 6. 三维项目状态与核验

- **执行状态（Agent Report）**：待执行、执行中、已提交、需返工、已关闭，以及最后一次有效上报时间。
- **证据状态（Evidence Verification）**：未提交、待核实、已核实部分/全部、不通过、已失效；每条附 exact version 与来源。
- **产品验收（User Acceptance）**：未发起、待验收、已接受、已退回；只有用户明确决定可修改。

工程验收：G0 完整交付物/版本；G1 可从 GitHub 查证的特定 commit 检查结论；G2 验收项证据映射（辅助，不等价于通过）；G3 独立体验审查非首版强制；G4 用户正式验收。

状态过期、GitHub 授权不足或外部消息乱序时，应显示“未知/待同步/待核实”，不得伪造「正常运行」或「CI 成功」。

## 7. 权限、隐私与人工控制

- 用户批准目标/范围/验收/预算、新 Baseline、主项目切换、正式产品验收、公开发布。
- Agent 只在受限资源、操作、版本、时限范围内工作；不得将报告、普通对话或交付自述作为授权证据。
- 首版宣发**人工发布**，雷达不控制社交账号；若未来需要外发权限，需独立审批设计。
- 私有仓库和消费者相关数据不得未经授权抓取、外发或公开；日志与内容素材需按必要性最小化。
- 用户暂停后平台撤权、外部进程停止确认和副作用回滚分别记录；不可把一个状态冒充另外两个。

## 8. P1 / P2 明确延后

**P1：** `collaboration.handoff` 的多 Agent 接收确认、独立 Reviewer、影子市场定期观察、跨项目自动经验推荐、深层产品留存 cohort、个性化创作风格优化、更多数据源适配。

**P2：** 全网实时监听、复杂 AI 机会评分、内置代码执行与 IDE、Agent 进程调度/模型路由、多平台自动发帖/广告投放、全量增长归因、CRM、付费结算管理。

**不是首版阻塞项**：真人出镜、自动剪辑、多个并行市场、多个并行主实验、产品命名与品牌视觉系统、完整知识图谱。

## 9. 首版验收总则与实测要求
