# v1.7 · 机会发现质量反馈与人工误报闭环

## 现在能做什么？

进入「机会简报 → 信息源与信号 → 重复问题候选」，在每个候选组中：

1. 查看原文 URL、署名和站点，**共同标题词**、组内最低标题相似程度；它们是可解释的词汇依据，而非大模型置信度。
2. 若归一化标题重复、较长摘要完全相同，或同站点作者署名相同，界面会标注 **可能转载 / 重复发帖**。这不是事实判定，仍需打开原文核查是否为同一作者、转载、评论或独立经历。
3. 确认可能属于同一消费者问题时，使用「标记为同一问题线索」，必须说明人工判断理由。此操作只记录线索相关性，**不创建机会、不自动关联证据、更不能确认付费需求**。
4. 如果属于无效归组，点「忽略这组」，选择 **疑似转载或重复发帖 / 实际是不同问题 / 与消费者问题无关 / 其他原因**，填写核查理由。误报分类只描述 Owner 的判断，不等于客观真相。
5. 通过「查看已忽略」可以恢复；如果该组新加入/失去成员，或来源标题、摘要、署名变化，旧标签不会自动应用，新版本必须重新审查。

## 质量反馈面板

本版统计的是**当前窗口内**的手动标签：组数、已核查数、Owner 判为同一问题但尚未验证的组数、人工排除数及疑似重复发布数。由于来源含身份无法核验的公开讨论，这些数字**不等于独立消费者数量、实际需求或模型精度**。如果有效标签不足五组，不计算人工相关判断比例；即使达到五组，其比例也只表达被主动核查的样本，存在选择偏差。

新增 `GET /api/discovery/quality`，只允许 Owner 访问。分组核查接口支持 `action: confirm` 与分类字段，保留 `dismiss/restore`，旧版未提供类别的忽略请求兼容地归为 `other`。修改操作可使用 `expected_revision`，前端必须提交当前成员指纹。数据仍只保存在本地 SQLite。

## 技术实现

- `src/discovery.mjs`：可解释的两两相似计算、最多显示 12 个共享词片、疑似转载启发式、手动反馈与当前窗口统计。
- 标题相似依旧是**保守的词汇** Jaccard 规则，并非跨语言语义嵌入或分类器。短文本、同义不同字、跨语言表达可能无法聚合。相同标题或摘要可能只是模板，不保证同一篇文章。
- 指纹绑定组内信号 ID、归一化标题、摘要和作者署名。仅改变 URL 中无关参数或不同采集时间并不意味着新的原文证据。
- `public/app.js`、`public/i18n.js`、`public/style.css`：显示风险、依据、反馈表单及中英文提醒。
- `tests/discovery-precision.test.mjs`：自包含小型**离线示例对**和标注状态回归；`tests/http.test.mjs`：授权和后端行为；`scripts/browser-smoke.py`：Chromium 直接通过真实 Node HTTP + 临时 SQLite 点击确认、关联。

## 不应做出的结论

- 自动聚类一定找到了真实市场机会。
- 转载标记一定正确。
- 用户人工标记的「同一问题」意味着独立消费者、复购或付费意愿得到核验。
- 少量离线测试样本的完全正确等同于生产准确率。
- 无真实跨语言语义模型、真实人审基准集时声称提高了召回率或 precision。

## 下一步真实评估

从已经运行的公开来源中人工抽样，先建立 30–50 对带原文和复核理由的**有许可、可追溯的标注样本**（含误报、漏报、转载、不同语言表达）；对每个模型版本在固定样本上计算 precision/recall，再决定是否引入小型多语言嵌入检索或候选重排。这一步需要真实样本和明确的隐私及版权边界，暂未作为 v1.7 完成能力。
