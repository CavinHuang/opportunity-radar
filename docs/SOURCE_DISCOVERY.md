# Northstar · 信息源与机会发现

本功能是**线索处理工作台**，不是消费者需求事实引擎。任何 RSS 新闻、产品上新、转帖、手工摘录或 AI 分析都只能作为待调查信号。

## 快速开始

1. 运行 `npm start`，进入 **机会简报 → 信息源与信号**。
2. 点击「添加 RSS」，或选择公开来源模板后检查实际 URL、市场和筛选条件，再确认订阅。
3. 点击「扫描全部」或来源的单独「扫描」。失败原因会出现在该来源下方；也可以暂停来源，保留既有信号。
4. 用待处理、已收藏、已忽略、已转机会、全部等标签和关键词搜索查找文章。点击来源链接亲自核查原文。
5. 如对应平台没有 RSS，点击「保存网页线索」，手工录入真实标题、摘要及 URL。
6. 通过「新建机会」或「关联现有机会」记录为什么值得继续取证。证据会带来源 URL 并明确非独立、未验证。新增机会只有获得具体假设、预算、停止条件后才可以批准实验。
7. 回到机会简报查看本周至多 3 项重点候选和**完整机会池**。可以选择观察或放弃，不强求每个点子都变成项目。

## 数据与决策约束

- 开箱没有假数据，也不暗中安装来源。截图中所有 `[DEMO]` 记录仅来自独立演示数据库。
- 不需要连接付费 LLM 才能采集、筛选、归档、发现候选机会。
- 仅保存公开来源的标题、精简摘要、URL 和时间信息；不复制整篇受版权保护的文章。
- 同一个 URL 的不同 `utm_*` / `fbclid` / `gclid` 参数会归并为一个信号。**不同 URL 仍可能是同一个消费者的转帖**，须人工核查来源关系。
- 关键词只是大小写不敏感的标题/摘要包含匹配，并非语义理解或自动需求验证。
- 模型生成草稿只是人工决策辅助。不会自动批准实验、修改预算或发布。

## 来源可靠性与安全

- 每个 RSS/Atom 来源必须采用公开 HTTPS URL，不能包含用户名、密码、非标准端口或本机/内网主机名。
- 扫描前查询域名，拒绝解析到私有地址；每次重定向重新检查地址。为零外部依赖，此版不具备 DNS 解析到实际连接 IP 的完整强制绑定，在不可信网络中不应把本地服务暴露给未授权人员。建议只添加自己信任的来源。
- 超过 1MB 的 RSS 响应会被拒绝；每个 RSS 最多处理前 25 项，最多管理 30 个来源；抓取出现错误时保留历史信号，不会伪造成功结果。
- 网站的 robots、请求频率、协议或风控可能禁止 RSS 获取。此时应调整来源或使用手动链接记录；不尝试绕过网站的登录与访问控制。
- 非 RSS 的站点（如部分国内社交平台）暂时不支持自动抓取；可手工收集真实网页链接。

## API（Owner 权限）

| 接口 | 说明 |
|---|---|
| `GET /api/sources` | 读取订阅列表及同步状态 |
| `POST /api/sources` | 新增来源：`url,title,market,keywords` |
| `PATCH /api/sources/:id` | 编辑标题、市场、关键词、启停；必须携带 `expected_revision` |
| `POST /api/signals/scan` | 扫描所有启用来源；传 `source_id` 仅扫描指定来源 |
| `GET /api/signals?status=new&q=&offset=0&limit=30` | 分页筛选与状态计数 |
| `POST /api/signals/manual` | 手工保存 URL、标题、原始摘要，标明未核实 |
| `POST /api/signals/:id/triage` | `new/saved/dismissed`，须携带 `expected_revision` |
| `POST /api/signals/:id/import` | 用户将一条信号转换为一个新机会；自动附加原始来源 |
| `POST /api/signals/:id/link` | 将信号关联到已有机会：`opportunity_id` |
| `POST /api/opportunities/:id/status` | 手工改为 `candidate/watching/dismissed`；必须有 `expected_revision` |

以上均为本机 Owner API，不对外暴露信号编辑权限给 Coding Agent。

## 自动化与实际验收

- `npm run check`：单元、HTTP、MCP、存储规则测试。
- `python scripts/capture_screenshots.py`：隔离数据库启动真实 Node 后端，执行 Chromium 真正前端渲染、信号收藏及导入点击，生成 README 截图。不触碰生产数据库；如果 Chromium 本地导航遭拦截，则使用真实 API 响应桥接，**不等同于直连浏览器网络 E2E**。
- T1–T4 Coding Agent 与真实消费者试点仍需另外验证。
